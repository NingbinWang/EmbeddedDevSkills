# 时间段任务调度器

根据当前系统时间，匹配用户定义的时间段，执行对应任务。

---

## 一、启动流程（交互式配置）

当用户触发本技能时，**必须按以下步骤交互式引导用户完成配置**。

### Step 1: 检查当前目录是否已有配置

```bash
ls ./schedule.yaml 2>/dev/null
```

- **存在** → 读取并展示已有配置，询问用户:
  ```
  当前目录已存在 schedule.yaml，内容如下:
  [展示内容]

  你想要:
    A) 使用现有配置直接运行
    B) 重新配置（覆盖现有配置）
    C) 在现有配置基础上添加/修改
  ```
  - 选 A → 跳到"执行流程"
  - 选 B → 继续 Step 2
  - 选 C → 继续 Step 2，在现有配置上修改

- **不存在** → 继续 Step 2

### Step 2: 询问用户需要什么时间段做什么任务

依次询问以下问题（使用 clarify 工具）：

**问题 1: 选择时间段**

```
你想在什么时间段执行任务？（可多选，逐个添加）

可用的预设时段:
  1) early_morning — 早间 (05:00-08:00)
  2) morning       — 上午 (08:00-12:00)
  3) afternoon     — 下午 (12:00-18:00)
  4) evening       — 晚间 (18:00-22:00)
  5) night         — 夜间 (22:00-05:00)
  6) 自定义时间范围（如 09:30-11:00）
  7) 工作日限定（如 Mon-Fri 09:00-18:00）
  8) 周末限定（如 Sat-Sun 10:00-16:00）
```

**问题 2: 该时间段的任务名称**

```
给这组任务取个名称（如"晨间巡检"、"下午检查"）:
```

**问题 3: 该时间段的具体任务**

```
在这个时间段需要执行什么任务？（逐个添加）

任务类型:
  A) 命令任务 — 执行 shell 命令（如 df -h、ps aux）
  B) Skill 任务 — 调用其他 skill（如 arxiv、github-issues）

请描述第一个任务:
```

用户描述后，继续问:
```
还有更多任务要添加吗？（没有的话回复"没有"或"完成"）
```

循环添加直到用户说没有。

**问题 4: 是否添加更多时间段**

```
还需要添加其他时间段的任务吗？
  A) 是，继续添加
  B) 不用了，生成配置
```

循环回到问题 1 直到用户选择生成。

### Step 3: 生成配置文件

根据用户回答，在当前目录生成 `./schedule.yaml`：

```yaml
# 时间段任务调度配置
# 生成时间: YYYY-MM-DD HH:MM:SS
# 触发方式: 对 Hermes 说 "运行定时任务"

schedule:
  - time: "morning"          # 或 "09:30-11:00" 等
    name: "晨间巡检"
    tasks:
      - type: command
        name: "系统健康检查"
        command: "df -h / && free -h && uptime"
      - type: skill
        name: "搜索论文"
        skill: arxiv
        action: "搜索最近的 LLM 论文"

default_task:
  name: "默认"
  action: "当前不在任何定义的时间段内，无任务需要执行"
```

### Step 4: 展示配置并询问是否修改

生成后立即展示完整内容并询问：

```
============================================================
  已生成配置文件: ./schedule.yaml
============================================================

[完整展示文件内容]

============================================================

配置是否满意？
  A) 满意，直接运行
  B) 需要修改
```

**选 A** → 跳到"执行流程"

**选 B** → 进入修改流程:

```
请告诉我需要修改什么地方？例如:
  - "把 morning 的时间改成 07:00-10:00"
  - "给 afternoon 添加一个 git 检查任务"
  - "删除 night 时段"
  - "把任务名称改成'早间简报'"
```

根据用户描述修改配置，修改后**再次展示并询问**，循环直到用户满意。

## 二、任务模板参考

以下是各类任务的标准写法，供生成配置时使用：

### 命令任务 (type: command)

```yaml
- type: command
  name: "任务名称"           # 用于显示，任意取名
  command: "shell 命令"      # 单行命令

# 或多行命令:
- type: command
  name: "复合检查"
  command: |
    echo '=== 磁盘 ===' && df -h /
    echo '=== 内存 ===' && free -h
    echo '=== 负载 ===' && uptime
```

### Skill 任务 (type: skill)

```yaml
- type: skill
  name: "任务名称"           # 用于显示
  skill: arxiv              # skill 名称（从 skills_list 获取）
  action: "搜索最近的 AI 论文"  # 传递给 skill 的指令
```

### 常用 Skill 任务示例

```yaml
# 搜索论文
- type: skill
  name: "论文搜索"
  skill: arxiv
  action: "搜索 transformer 相关最新论文"

# 检查邮件
- type: skill
  name: "邮件检查"
  skill: himalaya
  action: "列出未读邮件"

# GitHub Issues
- type: skill
  name: "Issue 检查"
  skill: github-issues
  action: "列出当前仓库的 open issues"

# 代码审查
- type: skill
  name: "PR 审查"
  skill: github-code-review
  action: "审查最新的 PR"

# 知识库整理
- type: skill
  name: "笔记整理"
  skill: llm-wiki
  action: "整理今日学习笔记到知识库"

# 发推
- type: skill
  name: "发推文"
  skill: xurl
  action: "发一条今日总结的推文"
```

### 时间段格式

| 写法                      | 含义                   |
|--------------------------|------------------------|
| `"morning"`              | 08:00-12:00            |
| `"afternoon"`            | 12:00-18:00            |
| `"evening"`              | 18:00-22:00            |
| `"night"`                | 22:00-05:00 (跨午夜)    |
| `"early_morning"`        | 05:00-08:00            |
| `"09:30-11:00"`          | 自定义精确范围          |
| `"Mon-Fri 09:00-18:00"`  | 工作日限定              |
| `"Sat-Sun 10:00-16:00"`  | 周末限定                |

## 三、执行流程

当用户说"运行定时任务"且配置已就绪时，按以下步骤执行：

### Step 1: 获取系统时间

```bash
date '+%Y-%m-%d %H:%M:%S %A %Z'
```

### Step 2: 读取配置

读取当前目录的 `./schedule.yaml`（如不存在则读 `~/.hermes/schedule.yaml`）。

### Step 3: 匹配时间段

| time 字段           | 匹配规则                                    |
|---------------------|--------------------------------------------|
| `morning`           | 08:00 <= 当前 < 12:00                      |
| `afternoon`         | 12:00 <= 当前 < 18:00                      |
| `evening`           | 18:00 <= 当前 < 22:00                      |
| `night`             | 当前 >= 22:00 或 当前 < 05:00               |
| `early_morning`     | 05:00 <= 当前 < 08:00                      |
| `HH:MM-HH:MM`      | 起始 <= 当前 < 结束                         |
| `Weekday HH:MM-HH:MM` | 先匹配星期，再匹配时间范围                |

多个时间段同时匹配时，全部执行。

### Step 4: 执行任务

对每个匹配到的时间段中的 tasks 列表，按顺序执行：

- **type: command** → 用 terminal 工具执行 command 字段
- **type: skill**   → 用 skill_view() 加载 skill，按 action 指令操作

### Step 5: 汇报结果

```
=== 时间段任务调度报告 ===

当前时间: YYYY-MM-DD HH:MM:SS 星期X CST
匹配时段: [时段名称列表]

--- [时段1名称] ---

  [任务1名称] ✅ 完成
  结果摘要...

  [任务2名称] ❌ 失败
  错误信息...

=== 调度完成 ===
已执行: X/Y 个任务
```

---

## 四、注意事项

1. **配置文件位置**: 优先读当前目录 `./schedule.yaml`，其次 `~/.hermes/schedule.yaml`
2. **跨午夜时段**: `night` (22:00-05:00) 特殊处理，hour < 5 视为 night
3. **多任务匹配**: 若同时匹配多个时间段，全部执行
4. **Skill 加载失败**: 记录错误，继续执行其他任务
5. **交互式循环**: 修改配置后必须再次展示并确认，直到用户满意
6. **任务顺序**: 按 tasks 列表中的顺序依次执行
